# 주문 배송비 누락 수정

## 원인과 적용 기준

`Orders.create()`가 `total_amount`를 단가 × 수량으로만 저장했다. 주문 상세의
`payment.totalPaymentAmount`, 목록의 `totalAmount`, 결제 예약 금액과 자동결제 요청은
이 저장값을 사용하므로 배송비가 함께 누락됐다.

총액을 `단가 × 수량 + 배송비`로 수정한다. 배송비는 주문당 한 번 적용한다.
단가 4,500원·수량 1·배송비 3,000원이면 표시 및 청구 총액은 7,500원이다.
수량 5인 하나의 주문이면 25,500원이며, 1개씩 주문 5건이면 각 7,500원이다.

AI 낙찰 평가의 공구당 배송비 1회 계산과 주문당 청구 기준은 서로 다르다.
이번 수정은 QA가 요청한 주문별 7,500원 기준을 적용하며 AI 평가식은 변경하지 않는다.

## 기존 주문 및 배포

V23 마이그레이션은 아래 조건을 모두 만족하는 기존 주문만 보정한다.

- 주문 상태가 `PAYMENT_PENDING`
- 배송비가 양수이며 저장 총액이 정확히 단가 × 수량인 누락 건
- 연결된 결제 기록이 없음

이미 총액이 올바른 주문에는 더하지 않는다. 결제 예약·시도·승인 기록이 있는 주문은
결제 금액 및 멱등성 키의 일관성을 위해 자동 보정에서 제외한다.
마이그레이션은 주문·결제 테이블의 쓰기 잠금을 사용하므로 트래픽이 적은 시간에 적용한다.
구버전 주문 생성 워커를 중지한 뒤 적용해야 마이그레이션 후 구버전이 잘못된 주문을 다시 만들지 않는다.

QA 주문 `ORD-1790413719407-…`의 정확한 번호와 실제 결제 기록은 이 작업에서 조회하지 않았다.
dev 배포 후 상세·목록·예약 금액을 확인해야 한다. 아래 조회로 보정에서 제외된 누락 건을 점검할 수 있다.

```sql
SELECT o.id, o.order_no, o.order_status, o.total_amount,
       o.price * o.sum + o.delivery_fee AS expected_amount,
       p.id AS payment_id, p.payments_status, p.total_amount AS payment_amount
FROM orders o
LEFT JOIN payments p ON p.order_id = o.id
WHERE o.delivery_fee > 0
  AND o.total_amount = o.price * o.sum;
```

이미 예약된 결제는 외부 요청 여부와 처리 상태를 확인한 후 별도 보정해야 한다.
승인된 결제 이력을 새 총액으로 덮어쓰거나 차액을 자동 추가 청구하지 않는다.
이번 작업은 코드·마이그레이션 작성과 로컬 테스트이며 dev 데이터 변경이나 결제 호출을 수행하지 않는다.
